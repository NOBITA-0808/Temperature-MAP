# Pico講座 センサーマップ・写真共有 更新版

作成日：2026-10-19。添付の server(1).py / map(1).html / main確認用.txt と追加仕様を基に更新。
Render上の公開中サービス・GitHub・Pico実機にはまだ反映していません。

## まず行うこと

1. 現在のGitHubのソフト一式とSQLiteデータベースを別途保存します。
2. ZIPを展開し、Renderに接続した既存リポジトリの server.py / requirements.txt を更新します。
   templates/ と static/ はフォルダごと追加・更新します。README.md と restore_backup.py も保存します。
   ZIP内の sensor_course_v2 フォルダ自体を置く場合は、RenderのRoot Directoryも sensor_course_v2 にします。
   既存リポジトリのルートに中身を置く場合はRoot Directoryを変更しません。
   pico/main.py はPico用なので、サーバー起動用に使わないでください。
3. Renderの永続ディスクが `/var/data` に接続されていることを確認します。
   既存の `DB_PATH` がある場合はその値を引き継ぎます。下記は `/var/data/sensor_data.db` を利用中の場合の例です。
   現在のDBが別の場所にある場合、パスを確認せずに変更しないでください。違うDBを開くと空のデータに見えます。
4. Renderの環境変数と起動コマンドを下記のとおり設定して再デプロイします。
5. `/login` で初期管理者として入り、管理画面でメンバー・機器を登録します。
6. 各機器のキーをPico側 `DEVICE_KEY` に設定し、先に1台で送信・地図・グラフ・写真を確認します。
   それから他の講座メンバーに展開してください。

**更新後はキーのない旧Picoプログラムからの送信が401エラーになります。既存の閲覧URLもログイン必須です。**
機器名を従来と同じ `pico_test1` などで登録すれば、過去の観測履歴につながります。

## Renderの設定

Build Command:

```sh
pip install -r requirements.txt
```

Start Command（1ワーカー。`--preload` は付けません）:

```sh
gunicorn --bind 0.0.0.0:$PORT --workers 1 --threads 4 --timeout 180 --no-control-socket server:app
```

Health Check Path: `/health`

`.python-version` はPython 3.12系列を指定しています。
SQLiteと写真バックアップの整合性確保にプロセス内ロックを使うため、複数ワーカー・複数インスタンスでは使わないでください。

| 環境変数 | 設定例・説明 |
|---|---|
| `SECRET_KEY` | 必須。32文字以上のランダム値。下記コマンドで生成し、出力をそのまま設定。GitHubには掲載しない |
| `ADMIN_USERNAME` | 初期管理者ID。例 `miyamoto`。英数字・_・.・-で3〜40文字 |
| `ADMIN_PASSWORD` | 初期管理者パスワード。12〜128文字。自分で決めた固有の値 |
| `DATA_DIR` | `/var/data`。写真・バックアップの保存先 |
| `DB_PATH` | `/var/data/sensor_data.db`。現在のDBのパスを確認して引き継ぐ |
| `COOKIE_SECURE` | `1`（既定）。RenderのHTTPSで使用 |
| `MAX_PHOTO_STORAGE_MB` | 写真合計上限。1GBディスクで始める例は `50`。省略時は500MBなので必ず契約容量に合わせる |
| `MIN_FREE_DISK_MB` | `100`（既定）。写真受信時に残すディスク空き容量 |
| `BACKUP_INTERVAL_HOURS` | `24`（既定）。起動後、約60秒間隔で期限を確認。`0`なら自動バックアップ停止 |
| `BACKUP_KEEP` | `7`（既定、最小2）。定期・手動バックアップの保存世代数 |

SECRET_KEYの生成（PCまたはRenderのShellで実行）:

```sh
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

初回の空のユーザーDBにだけ、ADMIN_USERNAME / ADMIN_PASSWORDで管理者を作ります。
作成後、初期パスワードの環境変数を削除してもアカウントは残ります。
管理者パスワードを変更するにはログイン後の「パスワード変更」を使います。
環境変数の変更だけでは既存アカウントのパスワードはリセットされません。
SECRET_KEYは再デプロイごとに変えず、同じ値を維持してください。変えると全員がログアウトします。

## 権限

| 操作 | メンバー | 管理者 |
|---|---|---|
| 地図・写真・グラフ・CSV | ログイン後に閲覧可能 | 可能 |
| 写真の登録 | 自分のIDで登録 | 可能 |
| 写真の説明・位置・日時の修正 | 自分の写真のみ | 全員分 |
| 写真・観測値の削除 | 不可 | ごみ箱へ移動、確認付き |
| ごみ箱から復元 | 不可 | 可能 |
| メンバー登録・停止・パスワード再設定 | 不可 | 可能 |
| 機器登録・停止・キー再発行 | 不可 | 可能 |
| バックアップ作成・ダウンロード | 不可 | 可能 |

管理者以外の新規登録は管理画面から行います。一般公開の自己登録機能はありません。
メンバーが停止されるとその人のログインと、その人が所有する機器からの送信を停止します。
パスワード再設定・変更時には、そのアカウントの既存セッションを無効化します。
キー再発行時には旧キーは直ちに無効になります。キーは発行時に一度だけ表示します。
ユーザーパスワードはハッシュ、機器キーもハッシュで保存し、平文ではDBに保存しません。

閲覧できる写真は講座全員で共有します。メンバーごとの非公開アルバムではありません。
写真の位置・自宅の位置・写っている人について、登録前に共有範囲を確認してください。

## 地図・グラフ・写真の操作

- 地図の観測地点、または一覧の行を押すと、地点別の気温・湿度・気圧グラフに切り替わります。
- 比較グラフは従来どおり全地点の気温を表示します。
- 表示日を指定すると、その日の観測地点・グラフ・写真・CSVを表示します。日付境界は日本時間です。
- 日付を解除すると、地図の観測値は最新、グラフは過去24時間、写真は全期間です。CSVは全期間の有効データです。
- 「写真を登録する」を開き、写真を選びます。GPS・撮影日時を自動読取します。
- GPSがなければ「地図から場所を指定」を押して、地図の撮影場所をクリックします。緯度・経度の手入力も可能です。
- 撮影日時・説明を確認し、登録します。EXIFに時差がない写真は日本時間と仮定するため、海外写真などは修正してください。
- サムネイル、または写真一覧を押すと拡大写真が開きます。近接した写真は地図上で数字にまとまります。
- 本人または管理者には「説明・場所・日時を編集」、管理者には「ごみ箱へ移動」を表示します。
- 写真の近隣観測値は、撮影位置から5km以内、撮影時刻の前後60分以内の有効データから選びます。
  まず距離、同距離では時間差が小さい値を使い、観測場所・観測時刻・距離・時間差も表示します。
  該当しなければ「データはありません」と表示します。撮影場所そのものの気象値を保証するものではありません。

対応写真：JPEG / PNG / WebP / HEIC（pillow-heif）。1リクエスト最大20MB、40メガピクセルまで。
フォーム全体も20MB上限に含まれるので、20MBちょうどの画像は受け付けない場合があります。
保存時は長辺1600px以内のJPEGと96×96pxのサムネイルに変換し、EXIFは除去します。
**元の高解像度画像は保存しません。** 必要な原本は各自のスマホなどで保管してください。
位置と撮影日時はDBに記録し、写真ファイルもログインしているメンバーにだけ配信します。

## 容量と削除

写真・観測DB・バックアップすべてが永続ディスクを消費します。
写真の上限にはごみ箱内の写真も含み、バックアップの容量は含みません。
JPEGは圧縮済みなので、ZIPにしても大幅には小さくなりません。
7世代と作成中1世代を合わせ、写真保存量のおよそ9倍＋DB・移行前バックアップ・余裕を見込んでください。
例えば、写真50MBでも写真本体と8個のZIPで約450MB、写真500MBなら約4.5GBが目安です。
DBが大きい場合にはさらに容量が必要です。契約ディスク容量そのものを自動判定する機能はありません。
管理画面の使用量・空き容量と、RenderのDisk画面の両方を確認してください。

ごみ箱の写真・観測値は無期限保持とし、誤操作による完全削除を防ぎます。
この版では完全削除ボタン・自動完全削除処理は設けていません。
管理画面の観測値・ごみ箱一覧はそれぞれ最新100件です。大量の整理が必要になったら検索・ページ分けの追加対象です。
容量上限になると、新規写真は拒否されます。観測値は引き続き書き込まれるため、全体の空き容量も監視してください。

## バックアップと復元

- 初めて旧DBを更新する前に `backups/before-upgrade-日時.zip` を作成します。これは自動世代削除の対象外です。
- 起動時に定期バックアップがなければ作成し、以後24時間経過ごとに作成します（既定）。
- SQLiteのオンラインバックアップAPIでDBを複製し、写真ファイル・ごみ箱の写真もZIPにまとめます。
- 「今すぐバックアップ」も同じ7世代の対象になります。頻繁な手動作成で古い世代が繰り出される点に注意してください。
- ZIPは管理画面からダウンロードできます。PCや別の保存先に定期的にコピーしてください。
- 容量不足などで自動バックアップに失敗するとRenderのログに `Automatic backup failed` が出ます。
  管理画面のバックアップ一覧が更新されているかも確認してください。
- サービスが停止中の時間帯にはこのアプリの定期処理も動きません。
- 同じディスク内のバックアップだけではディスク全体の消失に対応できません。
- バックアップZIPにはアカウント・キーのハッシュと写真の位置情報が含まれます。一般公開・GitHubへのアップロードをしないでください。

復元は稼働中のDBに直接上書きせず、新しいディレクトリに展開します。
例として、RenderのShellで既存のバックアップから復元する場合：

```sh
python restore_backup.py /var/data/backups/backup-実際の日時.zip --destination /var/data/restored_20261019
```

実際のZIP名に置き換えてください。新しい空の復元先と、展開に必要な空き容量が必要です。
DB整合性・写真の存在・パスを検証します。任意のZIPを実行せず、このアプリの信頼できるバックアップだけを使用します。
成功後、Renderの環境変数を次の値に変更し、再デプロイします。

```text
DATA_DIR=/var/data/restored_20261019
DB_PATH=/var/data/restored_20261019/sensor_data.db
```

元の `/var/data/sensor_data.db` や写真には触れません。
復元するとアカウントのパスワード・機器キーもバックアップ時点に戻ります。
必要に応じてパスワード・キーを再設定してください。
移行前バックアップを旧プログラムで開けばロールバックできますが、追加した写真・メンバー情報は移行前には存在しません。

## Pico側の更新

添付の既存プログラムと同じ BME280、SSD1306、I2C0（SDA=GP4、SCL=GP5）を使います。
BME280のアドレスは0x76、OLEDは0x3Cです。
`bme280.py` と `ssd1306.py` は今使っているものをPico内に残します。

Thonnyで `pico/main.py` を開き、次を設定してPicoの `main.py` としてUTF-8で保存します。

```python
SSID = "自分のWi-Fi名"
PASSWORD = "自分のWi-Fiパスワード"
URL = "https://自分のサービス名.onrender.com/api"
NAME = "管理画面で登録した機器名"
DEVICE_KEY = "発行された機器キー"
LAT = 35.0
LNG = 135.88
SEND_INTERVAL_SECONDS = 600
```

旧プログラムはLED点滅300回×2秒で約10分間隔だったため、この版も600秒を引き継いでいます。
Wi-Fi切断時は再接続し、送信後の応答はfinallyで閉じます。観測記録時刻はサーバー受信時刻です。
ネットワーク障害中の観測値をPicoで蓄積し、あとで再送する機能はありません。
機器キーはHTTPSのAuthorizationヘッダーで送ります。JSON中のキーや共通パスワードは受け付けません。
MicroPythonのHTTPS証明書検証の扱いはファームウェア・HTTPライブラリに依存します。
実機の既存urequestsと組み合わせ、HTTPS接続・キー付き送信を確認してから講座に配布してください。
設定済みmain.pyはWi-Fiパスワードと機器キーを含むので公開しないでください。

## PCでの動作確認

```sh
python -m venv .venv
```

仮想環境を有効にし、`pip install -r requirements.txt` を実行します。
環境変数SECRET_KEY・ADMIN_USERNAME・ADMIN_PASSWORDを設定し、PCのHTTP確認に限り `COOKIE_SECURE=0` を設定してから：

```sh
python server.py
```

http://127.0.0.1:5000/ を開きます。ローカルのデータ保存先は `data/` です。
Renderに戻す際はCOOKIE_SECUREを1にします。デバッグモードは使いません。

自動テスト（Pico実機は不要）:

```sh
pip install pytest
python -m pytest tests -q
```

## ファイル

- server.py：認証・権限・観測API・写真処理・管理・バックアップ
- templates/：地図、ログイン、管理画面など
- static/：地図・グラフ・写真のJavaScriptとスタイル
- pico/main.py：機器キー対応のPico送信プログラム
- restore_backup.py：新しい空の保存先への復元
- requirements.txt：サーバー側依存ライブラリ
- tests/test_course.py：権限・移行・写真・復元などのテスト
- 検証結果.txt：この版で実施した検証と実機未確認事項

地図タイル（OpenStreetMap）とLeaflet・Chart.jsなどの配信元への接続が必要です。
これらの外部配信が遮断される環境では地図・グラフが表示されません。
